# PR & Release Templates and Guidelines

Purpose: Standardize PR quality and release notes so reviewers and stakeholders have the context they need.

Pull Request Checklist (add to PR description)
- [ ] Link to the related issue and one-pager
- [ ] Clear description of change and acceptance criteria
- [ ] Testing instructions and environments to reproduce
- [ ] Measurement owner assigned and metrics described
- [ ] Release Manager or Release window noted if applicable
- [ ] Security / SRE sign-off included when required

Release Notes Template
- Release name / number:
- Date:
- Summary:
- Notable changes:
- Rollback steps:
- Migration steps (if any):
- Known issues and workarounds:
- Owners / contacts:

Guidance
- Small PRs make reviews faster and reduce risk
- Use the checklists in docs/ to validate readiness before requesting reviews
